# ko

Ko's personal opinionated CLI. Thin wrappers around SDKs I use often, built so both I and AI agents (Claude Code via bash) can lean on it.

## Subcommands
- `ko exa search|get` — Exa **semantic** web search + URL → markdown. `search` shows a query-relevant summary per hit by default; `--highlights` (bounded key sentences, the agent default — ~10x fewer tokens) or `--long` (full-text excerpt). `--type` = search algorithm (`auto` default; `neural` is the only type that returns a real relevance `score`; `fast`/`instant`/`deep`/`deep-reasoning`); `--category` focuses the index (`'research paper'` = the scholarly index, upgrades the `--domains .edu` trick; news/company/pdf/'personal site'/'financial report'/people); `--max-age-hours` = cache freshness (0 always live-crawl, -1 cached-only, omitted = live-crawl fallback). Both `--type`/`--category` validate → exit 2 on a bad value, as does `--domains` + `--exclude` together (Exa's API rejects the pair). A `--long` excerpt that hit the cap ends in `[... truncated at N characters]` — the library asks Exa for one character of headroom so "was it cut?" is knowable rather than guessed. `get` returns clean markdown; a dead URL is reported on stderr with Exa's per-URL status (`(error)`) and skipped (exit 0 if any URL succeeds). SDK values mirror `exa_py`; `ko prompt exa` is the when-to-use brief. Wart: the SDK papers category is `'research paper'`, **not** `publication`.
- `ko arxiv search|fetch` — arxiv search (**relevance-ranked**; `--recent` = newest-first for browsing a `cat:cs.LG`) + paper-to-markdown. For cross-publisher relevance, prefer `ko papers search`.
- `ko gsheets info|tabs|get|find|pdf | set|put|header|add-tab|dup-tab|delete-tab|insert-rows|insert-cols|replace|new|clear|auth` — read **& write** Google Sheets via OAuth. `pdf [tab]` = print-ready PDF (A4 portrait fit-to-width default; `--size/--landscape/--gridlines`) via the sheet's export endpoint — the Sheets v4 API has no PDF export; our existing token works, no Drive scope needed. `dup-tab` clones a tab with all its formatting/formulas (the new-invoice move: dup last month's, then `set`/`replace` the values); `delete-tab` verifies the tab + confirms on a TTY (`--yes` for pipes/agents); `replace` = find&replace (requires `--tab` or explicit `--all-tabs`); `insert-rows`/`insert-cols` insert before a 1-based row/column letter, inheriting formatting from the row above / column to the left (`--no-inherit` for blank) — one lib fn (`insert_dimension`, SDK zero-based semantics), two CLI spellings. Accepts a URL, bare ID, **or a learned name**: ko auto-learns each sheet's title→id (from `info`/`tabs` or a range-less `get`) into a state-dir cache — `ko gsheets alias` lists them, `alias <name> <id-or-url>` pins a custom one (pins outrank learned titles and never get overwritten; ambiguous names list candidates and exit 1, the `tt done` pattern). `get` with no range reads the first tab's used range, a bare tab name reads that tab whole (no more guessing `A1:Z200` bounds), and rows come back **padded to a true rectangle** (the API returns ragged rows — column 7 must not become column 5 under `cut -f`). Reads use the readonly scope; writes need read+write (`ko gsheets auth` grants it by default). Shape-aware writers (`set`/`put`, library `write_values`/`write_ranges`/`write_df`) refuse to clobber non-empty cells unless `--overwrite` — the error lists them. `write_df` duck-types polars **or** pandas (neither is a dep). Generic port from the NibbleEdge `ne` tool; no project-specific shortcuts.
- `ko doc <file>` — PDF/Office/image → plain text via liteparse (local, no models). Bare shortcut: `ko <file>` routes here when the arg is an existing file.
- `ko pdf <file.md>` (alias **`ko md-to-pdf`**) — markdown → print-ready PDF via **WeasyPrint 69** (A4, pygments code highlighting, tagged/accessible by default). The inverse of `ko doc`; ported from `ops/scripts/md_to_pdf.py`, whose CSS is reused verbatim. **Prints the output path to stdout** so it chains: `-a "$(ko pdf status.md)"` into `ko gmail draft new`. Four flags total (`-o`, `--style`, `--letterhead/--no-letterhead`, `--brand`) — deliberately trimmed; see the WORKLOG entry for what was cut and why. **Styles** are named bundles of page furniture, not whole stylesheets: `note` (default — typography + `brand · title (Printed date)  N / M` footer), `report` (+ page-1 letterhead, auto Contents from the H2s, numbered sections — the ops handover look), `bare` (typography only), plus any `~/.config/ko/pdf/<name>.css` which layers on `note`. That style dir is the **only** way to add CSS (a `--css` flag would be a second answer to one question, and a named style is reusable where a flag isn't). Set via `--style` / front-matter `style:` / `[pdf] style`. Defaults follow **Quarto**, where `toc`/`number-sections` are both opt-in — a Contents block listing two headings is furniture, not navigation. Numbering is **tied to the TOC** (the TOC's "N." prefixes must match the body counter; splitting them renders a doc that disagrees with itself). Identity comes from a brand.yml ([brand-yml](https://posit-dev.github.io/brand-yml/)) resolved `--brand` > `KO_BRAND` > `[pdf] brand` — the ops script needed `--brand` on every call and silently printed a `yourbrand.dev` placeholder when you forgot, so an unresolved brand now warns on stderr. Front matter: `title`/`date`/`author` (the last two land in the PDF's own metadata) and `style`. `<div class="page-break"></div>` forces a page; markdown-it runs the **commonmark** preset with `html: True` and *without* linkify/typographer (both are inert on that preset anyway, and typographer would rewrite `--flags` in prose to en dashes). `docs/pdf-sample.md` is the fixture — it exercises every element and `tests/test_pdf.py` renders it in every style. The resume stylesheet **stayed in ops** — one document's layout isn't a generic renderer's job. Needs pango/cairo (`brew install pango`); since dyld reads its search path at process start, the HTML is built in-process and rendered by a short-lived child interpreter with `DYLD_FALLBACK_LIBRARY_PATH` set — zero setup for the caller, agents included.
- `ko fetch <url>...` — URL → markdown, deterministic routing: arxiv→arxiv2md, YouTube→transcript (via `ko yt`; fails loud when captions are off — no silent fall-through to the useless description page), PDF→~/Downloads+liteparse (`--no-save`), doi.org→OA copy, **reddit→reddit.synth.download** (third-party public mirror, straight host swap; direct reddit blocks every method — see the field-verified list in `fetch.py`; an empty mirror fails LOUDLY into Wayback of the original, and the durable path if the mirror dies is Reddit's OAuth API), else trafilatura, dead/empty→Wayback (`--archive` forces). Takes multiple URLs (`# <url>` sections split by `---`, exa-get exit semantics: per-URL failures to stderr, exit 0 if any succeeded); every successful doc prints one `[source · ~N tokens · detail]` banner to stderr so read-vs-pipe-into-llm is decidable before paying. Bare shortcut: `ko <url>`.
- `ko yt <url|id>` — YouTube → transcript via **youtube-transcript-api** (free, keyless, no video download; prefers manual subs over auto-captions). Plain text with paragraph breaks (>2s gaps); `--json` = `[{start, text, duration}]` snippets; `-s/--summarize` = one-shot LLM summary (`-m` overrides model). Accepts watch/youtu.be/shorts/live/embed URLs or a bare 11-char id. Stderr notes the ~token count. Future fallback for caption-less videos: Gemini native video understanding (URL as `file_data`, fractions of a cent) — package-first because it's free.
- `ko sum [<url|file>...]` — fetch + summarize in one move; no args = summarize piped stdin (`ko hn item 123 | ko sum`), so it doubles as the universal "--summary" without any source command growing one (the `ko yt -s` lesson: a per-command summarize flag grows `-m` but never a prompt, and you pipe around it anyway). Inputs route like `ko fetch`/`ko doc` (YouTube→transcript, PDF→text, reddit→mirror); multiple inputs = one summary each under `# <input>` sections, per-input failures skip (fetch's contract). Default prompt = the packaged `summarize` brief (strip fluff, keep the author's voice/opinions/facts, TL;DR first) — retune for good by dropping `~/.config/ko/prompts/summarize.md`, no release needed; `-p` = file path or brief name per run. Default model = gemini-3.5-flash-lite (`llm.SUM_MODEL`; `[llm] sum` / `KO_SUM_MODEL` / `-m` override) — summarization wants fast+cheap+long-context, not the smartest tier. Stderr shows the dispatch line (`[live · ~1,019 tokens → gemini-3.5-flash-lite]`) so a wrong routing choice is visible, then the usual cost note.
- `ko llm "<prompt>"` — one-shot LLM, stdin-aware, never has tools. `-f <file|url>` (repeatable) attaches inputs, routed like `ko sum` (PDF→text, YouTube→transcript): contents go before the prompt in flag order, piped stdin after — the opencode/simonw-llm convention (repeatable flag + plain shell paths; nobody parses `@file` in argv, `@` is a TUI-picker affordance). A named input that fails to read is fatal — no model call with half the context silently missing. `--schema <file.json>` = JSON-Schema-constrained output (pydantic-ai `StructuredDict`): compact JSON on stdout, prose-free; a bad schema file exits 2 before any model call, validation failure exits 1. Default = the **basic tier** (deepseek-v4-flash; `KO_DEFAULT_MODEL` → `[llm] model` → `[llm] basic` → baked; `-m` per-run, tab-completes models whose env key is set). Prints a cost note to stderr after each call. OpenRouter's catalog is fetched from its public `/models` and cached at `~/.cache/ko/openrouter_models.json` (24h TTL) so `-m openrouter:<slug>` completes.
- `ko models [--refresh]` — list model strings usable with `-m`, one per line. `--refresh` force-refetches the OpenRouter catalog past the 24h cache (for grabbing a just-released model).
- `ko brief [--raw] [-m model]` — morning brief: deterministic gather (today's calendar + unread gmail + `hn top` + `hf top`, each best-effort — an unconfigured source becomes a note, never a crash) → **one** cheap-model synthesis (scannable markdown: what's on, mail that matters, the 2-3 items worth a click). `--raw` prints the gathered sections and skips the LLM entirely. A scripted pipeline, NOT an agent loop. ⚠️ deliberate: sends calendar/email content to the configured LLM (noted in help).
- `ko logs [-n/--n] [--errors] [--json]` — recent local command logs. ko writes **one structured JSON event per command** via **loguru** (`~/.local/state/ko/logs/ko.jsonl`, serialized JSONL, weekly rotation: cmd label, duration, exit code, error type — **no args/secrets**, following PostHog's "one wide event per request"). loguru's default stderr sink is removed (ko's own output stays clean), and its sink model makes adding a sync trivial — a PostHog sync is just another `logger.add(sink)`. On by default; `[logs] enabled = false` (or `[logs] level = "debug"`) in config.toml. Best-effort — never breaks a command.
- `ko billing` — read-only balance + recent usage across paid services. v1: OpenRouter credits ($ remaining of total purchased; today/week/month usage). `--json`. One function per provider in `billing.py` (degrades gracefully like `ko doctor` — a missing key is a note, not a crash). pydantic-ai has no account-billing API, so we hit each provider's REST API directly.
- `ko hn top|search|item` — Hacker News via Algolia (no auth). `top` = hckrnews-style top 10/20 by points (`--now` = the live front page via Algolia's `front_page` tag — complementary: the tag only marks the *current* page, `top` does past windows); `search` defaults to last 12 months; `item` = story + comment tree as text.
- `ko hf top|search|info|get` — Hugging Face paper pages (no auth). `top` = Daily Papers in HF's *trending* order (upvote-driven with recency decay — not strictly upvote-sorted); `search` = semantic; `info` = metadata incl. github/models/datasets; `get` = paper as markdown. Same ids as arxiv — composes with `ko arxiv fetch`.
- `ko papers search|get|cites|refs|similar` — cross-publisher literature scouting via **OpenAlex** (no key; `mailto` polite pool; its `oa_url` IS Unpaywall's data). Takes DOIs, arxiv ids, or OpenAlex W-ids interchangeably. `search` = all publishers (TSV: year, cites, oa_status, title, doi, journal); `get` = full text via the OA copy + fetch pipeline, else a metadata card (authors, journal, S2 tldr, abstract reconstructed from `abstract_inverted_index`) — paywalled ≠ error; `cites`/`refs` = citation graph, most-cited first; `similar` = S2 recommendations (needs free `S2_API_KEY` — keyless S2 429s immediately, so tldr/similar degrade gracefully without it). Plus DOI routing in `ko fetch`: doi.org URLs resolve the OA copy first instead of 403ing on publisher landing pages. Design: `docs/papers-cli-design.md`. Known wart: a few OpenAlex DOI records are bad merges (wrong title, right abstract) — `search` for the title and use the W-id when a record looks off.
- `ko tv <title>` — movie/TV rating + overview + regional watch providers (`TMDB_READ_ACCESS_TOKEN`, free; AU default, `--country`).
- `ko x search|list|user|lists` — X via the official XDK (`X_BEARER_TOKEN`). `list <name|id|url>` = recent posts from a list (name = one of mine; a bare list id or `x.com/i/lists/<id>` URL reads **any public list**); bare shortcut `ko x ai` ≡ `ko x list ai`. `user <@handle|url>` = one user's timeline (further back than search's ~7-day window). `lists` = my lists, biggest first, with descriptions + member counts (owned lists; *followed* lists need a higher tier). `search` ≤7 days uses the recent index; `--days >7` switches to **full-archive** (years back); `--list <name|id|url>` scopes a search to a list (`ko x search "claude code" --list ai --days 90`). **Likes/bookmarks/home-timeline aren't available** — they need OAuth user-context, not the app-only bearer (which also can't self-identify, so set your handle via `[x] handle` in config.toml or `KO_X_HANDLE`; default `ko`). **Cost**: X is pay-per-use since 2026-02 (prepaid credits) — ~$0.005/post read (owned reads like `lists` $0.001), 2M reads/mo cap; so `ko x list --n 20` ≈ $0.10, `ko x lists` ≈ a cent. Full-archive/big `--n` cost more — mind them. [pricing](https://docs.x.com/x-api/getting-started/pricing)
- `ko tt lists|items|add|done|search` (alias **`ko todo`**) — TickTick read **& write** over the **Open API v1** (`https://api.ticktick.com/open/v1`). One static token does everything: TickTick → avatar → Settings → Account → **API Token** → `TICKTICK_API_KEY` (env or config.toml) — no OAuth, and the same token authenticates the hosted MCP. REST is the spine (~0.6s/call); the MCP is kept for the **one thing REST has no endpoint for: `search`** (~3s handshake, fuzzy, matches `content` too, covers completed tasks; its index trails writes by ~10-30s and it occasionally returns an empty result for a query that does match — re-run). `lists` = your lists, with the virtual **Inbox** first (GET /project omits it, but the literal id `inbox` works on every task route); `items <list>` = open tasks; `add "<title>" [list] --note <markdown> --due <when> --priority none|low|med|high --tag t` (no list → Inbox; `--due` takes today/tomorrow/`YYYY-MM-DD`/`YYYY-MM-DDTHH:MM` in the `[cal]` timezone, mirroring `ko cal add` — no date library); `done <query-or-id> [--list] [--yes]` resolves over **open** tasks (one `POST /task/filter {"status":[0]}` returns every open task, all lists incl. Inbox), completes on exactly one match, and on several **lists the candidates and exits 1** — never guesses (`--json` adds a `matches` array to the error object); confirms on a TTY, pipes/agents never prompt. Bare `ko tt` ≡ `lists`; `ko tt <list>` ≡ `items <list>`. **Markdown in `content` renders in the TickTick app** — write it verbatim (`desc` is CHECKLIST-only); quirks: single `~text~` is UNDERLINE (`~~text~~` is strikethrough), `::text::` is highlight, headings cap at 3 levels. Due dates are normalized to the local zone on read (TickTick returns UTC, which shows the *wrong day* for an all-day task). List names carry a glued-on emoji (`🛒Shopping`), so `resolve_list` compares on a match key (strip leading non-word chars, casefold). Deliberately absent: delete, un-complete, project create/delete, habits, focus.
- `ko gdocs get|push|replace|append|tabs|add-tab|comments|reply|shade-table` (alias `ko gd`) — Markdown ↔ Google Docs via OAuth (shared token; Docs + Drive `drive.file` scopes). `get` = Doc→Markdown (Drive export, tables included, pipe it); `push <file> [doc]` = Markdown→new Doc, or update an existing one in place (shows a diff + confirm, `--force` skips); `replace`/`append` = in-place edits; `comments`/`reply` = Drive comments; `shade-table` = header/totals cell shading (the bit Markdown can't do). **Tabs** (per-client shared docs keep one tab each): `tabs` lists them (index, title, tabId; sub-tabs indented; `--json`), `add-tab <title>` creates one (Docs API `addDocumentTab`; refuses a duplicate title), and `get`/`replace`/`append` take `--tab <title|tabId>` to scope to one tab. `get --tab` walks the tab's Docs-API body (Drive export can't scope to a tab); `replace --tab` scopes via `tabsCriteria` **and** refuses if it would orphan an open comment's quoted anchor (`--force` overrides — whole-doc replace keeps no such check). **Multi-tab safety**: a bare `replace`/`append` (no `--tab`) on a doc with >1 tab refuses (exit 2) — a bare `replaceAllText` rewrites *every* tab, and a bare append lands silently in tab 0; pass `--tab <title|id>` (or `--all-tabs` on `replace`). Single-tab docs stay frictionless. `push` can't target a tab (Drive Markdown import is whole-doc). What converts: see `docs/gdocs-markdown.md`.
- `ko cal [agenda] | day | find | add | cals` — Google Calendar agenda + quick-add (shared token; `calendar.readonly` + `calendar.events`). Bare `ko cal` = next 7 days across calendars (`--days`/`--today`); `find <text>` = events matching a title substring, forward or `--past` ('when was my last X'; borrowed from chota-bot); `add "title" <when>` accepts ISO / today / tomorrow (no date lib). Times in `[cal] timezone` (default Australia/Sydney). The default window anchors to the **start of today** (a 6pm query still shows the morning) and spans N calendar days → N day-headers; `--today` = calendar-today. `--json` is normalized: timed `start`/`end` are ISO8601 in the configured tz **with offset**, all-day events are bare `YYYY-MM-DD` with `all_day: true` and an **inclusive** `end` (Google's exclusive end.date −1 day; a single-day event has end == start). Minimal — no edit/delete/RSVP.
- `ko gmail [recent] | search | from | view | thread | attach | draft` — read Gmail + attachments + drafts (shared token). **Reads are read-only** (`gmail.readonly`). Bare `ko gmail` = recent inbox, one line/msg (id, date, from, subject + snippet; `-n`, `--unread`); `search "<query>"` passes Gmail's own syntax verbatim (`from:`/`newer_than:7d`/`is:unread`); `from <who>` shortcut; `view <id> [--full]` = one message; `thread <id> [--full]` = the whole conversation, oldest first. **`attach <id>`** (read-only): bare = list attachments (TSV/`--json`: index, filename, size, mimeType); `attach <id> [n] -o DIR` downloads the nth (or all) to DIR, never overwriting (appends -1, -2, …) — composes with `ko doc <file>`. **`draft new|reply|list|show|update|send`** (new/reply take `--attach <file>` repeatable + `--cc`; update takes `--to`/`--cc` to repair a recipient list) needs `gmail.compose` (one re-auth: `ko gmail auth --logout` then `auth`); a token lacking it errors with that hint. Reply threading = threadId + In-Reply-To/References + `Re:` (a subject override drops threadId, keeps the RFC headers); `--md` sends multipart/alternative (plain first, then markdown-it HTML); `update` re-fetches + preserves omitted to/cc/subject/threadId; header values reject newlines (injection guard). **Sending is opt-in**: `draft send` refuses unless `[gmail] allow_send = true` / `KO_GMAIL_SEND=1` (the outer gate, fires first), then guards against a body that says 'attached' with zero attachments (`--yes` overrides), then confirms (to/subject/attachment count; `publish rm` pattern) — draft-first is the default; a human sends from Gmail (no scheduled-send API). `--json` on reads adds per-message `labels` (Gmail labelIds) + `list_unsubscribe` (the header, empty on human mail) for newsletter-vs-human triage — the plain-text list is unchanged. No label/archive/mark-read *writes* (`gmail.modify`, later), no re-attaching originals in replies, no inline images/tracking.
- `ko publish new <dir> [--md|--bare|--hono]` / `ko publish preview [dir]` / `ko publish [dir]` / `ko publish list` / `ko publish rm <name>` — publish a folder to Cloudflare (`rm` deletes the Worker + forgets it locally; md/hono publishes also emit an agent-facing `llms.txt`). `preview` runs `wrangler dev` locally (real http; `file://` breaks ES modules + fetch). `new` scaffolds: default static (Tailwind+Alpine), `--md` (markdown doc site — generic `?page=` shell, README hub, sidebar TOC), `--bare` (just a CLAUDE.md of hints). Bare `ko publish [dir]` deploys; the folder's own `wrangler.jsonc` makes the name sticky → re-publish overwrites the same URL. Custom domain defaults to `<name>.khalido.dev` (`DEFAULT_DOMAIN`; override via `[publish] domain`). Creds: `KO_CLOUDFLARE_API_TOKEN`/`KO_CLOUDFLARE_ACCOUNT_ID` → config.toml → standard `CLOUDFLARE_*`. **Won't silently take over** an existing Worker name (checks the account; `--force` to override). Needs **wrangler** (pinned repo-local via `npm install`; `KO_WRANGLER` → `node_modules/.bin` → PATH → `npx wrangler@4`). `--hono` adds a Hono worker (API routes, D1/R2, optional `--pin` gate, cached `/api/data`); `ko publish --pin new` rotates the gate PIN. Cloudflare Access private pages + AI on sites deferred — see `docs/publish.md` / `docs/publish-ai.md`.
- `ko ai "<prompt>"` — **the default agent**: all Layer-1 toolsets (web, papers, HN, movies, read-only ~/code files) + its own memory (`memory/ai/`), medium tier, hard cap 30 model requests/run. One-shot or REPL, `-m`/`-r` as usual. Explicit command on purpose — intelligence is opt-in; a typo'd subcommand must never silently spend tokens. Specialists stay under `ko agent`.
- `ko agent research|repo|tv|sessions` — pydantic-ai agents. `research` (web+papers+HN, smart tier), `repo` (repo-explorer: "how does repo X do Y" over ~/code read-only — own repos + `refs/`; knows the refs/CLAUDE.md map, injected fresh per run; cites file:line; basic tier — a full exploration costs ~$0.0005), `tv` (movies/TV in AU, cheap model), no prompt = interactive REPL, `-m` overrides model, `-r <id>` resumes a saved session. `sessions` lists saved sessions (title/summary/tags once summarized; `--tag`/`--search` filter); `sessions summarize [--n] [-m]` = cheap-model title + one-line takeaway + tags per session into the SQLite index. **`ko a …` is a hidden shorthand for `ko agent …`** (e.g. `ko a research "…"`). See Agents below.
- `ko mcp inspect <name|url>` / `ko mcp call <name|url> <tool>` / `ko mcp overview <name|url>` / `ko mcp servers` — investigate/use MCP servers (ko is itself an MCP client). `overview` runs a pydantic-ai agent that connects (via `load_mcp_toolsets` — same mcp.json shape) and summarizes what the server is for + what's useful (reads only, won't call mutating tools; cheap model, `-m` to override) — handy for sizing up your own dev server. Target a **server name** from `~/.config/ko/mcp.json` (the standard `{"mcpServers": {...}}` shape — copy-paste-compatible with Claude Code/opencode; supports both `url`+`headers` and stdio `command`/`args`; secrets use `${ENV_VAR}` placeholders expanded from env/config at load, so the file is safe to check in) **or a raw URL**. `inspect` lists tools + resources + prompts (+ capabilities + the server's instructions); `--tool <name>` dumps that tool's full JSON input schema. `call` invokes a tool (`--arg k=v`). `servers` lists the registry. **`auth-info <url>`** is spec-aware (RFC 9728 + 8414): it walks a remote server's OAuth discovery surface *before* connecting — protected-resource + auth-server metadata, scopes, endpoints, DCR — and flags anything malformed (e.g. HTML where JSON should be); exit 1 on problems. `-H` overrides/adds headers, `--json` everywhere. **On failure** it prints the server's real HTTP status + body, the `WWW-Authenticate` header (the server saying *why*), and — if a Bearer token was passed — the token's decoded `aud/iss/scope/exp` claims (a wrong audience is otherwise invisible). (A 503 "not configured" = server-side, not your client.) A verb takes a name/url = client; a future `ko mcp serve` (no target) = ko as server. Listings to stdout, banner to stderr.
- `ko refs [pull] | setup | add <url> | list` — manage `~/code/refs` (read-only reference clones for ideas/patterns; `[refs] dir`/`KO_REFS_DIR` overrides). Bare `ko refs` = parallel `git pull --ff-only --prune` (worktree groups serial; prints only repos whose HEAD moved as `repo: old -> new`; confirm on TTY only — pipes/agents never prompt). `setup` = idempotent bootstrap: dir + the folder CLAUDE.md (written only if missing — it accumulates takeaways) + clones the **baked list** (`refs.BAKED_REPOS`, the opinionated default) plus `~/.config/ko/refs.txt` (machine-local, one URL/line, dotfile-synced). `add <url> [--note]` clones + stubs a CLAUDE.md entry + appends to refs.txt so setup restores it anywhere. The dir itself is the truth for pull/list; the lists exist only for bootstrap. Pull logic ported from dotfiles/gitupdateall.py.
- `ko prompt [name] [--copy]` — my opinionated "how I build X" notes, pulled by name to load into an agent ("get `ko prompt sveltekit-app`") or copy-paste (`--copy`). Bare `ko prompt` lists (TSV: name, description); `ko prompt <name>` prints the markdown. Briefs ship in `src/ko/prompts/*.md`; add or override per machine in `~/.config/ko/prompts/*.md` (a user file wins by name). A meta-layer on top of generic llms.txt — my picks + the gotchas, with links out to the canonical docs. The tool is just a thin loader; the content is hand-written.

## Principles
- **Opinionated, not generic.** Do what I actually do, the way I do it. Defaults match my habits.
- **Thin wrappers.** Each module (`exa.py`, `arxiv.py`, `gsheets.py`) is a self-contained domain module over one upstream SDK. Keep parameter names matching the SDK so agent-written code composes with upstream docs.
- **Help lines carry their weight.** Every subcommand and flag has a concise, useful `help=`. Assume humans and agents skim `--help` and nothing else.
- **Human-readable and pipeable by default.** Plain text / TSV. Add `--json` when structure matters. Errors to stderr. `typer.Exit(0)` for "no results" (not an error).
- **One file per domain.** `cli.py` registers subapps; each module owns its logic. No shared `utils/` until three things need the same thing.
- **`--help` is the contract.** Machine-friendly output is a design constraint, not an afterthought.

## Agents (`src/ko/agents/`)
- **Tools declared once** as `FunctionToolset`s in `_toolsets.py` (`web` = exa+fetch, `papers` = arxiv+hf+OpenAlex citation-graph [search/get/cites/refs], `news` = hn [top/front_page/search/discussion — search passes through since_months/by_date/min_comments], `tmdb`, `files` = read-only list_dir/read_file/grep/glob over `~/code` for the repo agent (names/shapes match Claude Code's Read/Grep/Glob priors; listings show ≈token sizes so the model judges read-whole vs grep-first) — `agents/_files.py`: containment resolves symlinks BEFORE `is_relative_to` (thinker's `resolve_in` + harness's TOCTTOU ordering), read-only by construction (no write tools exist), capped output, ripgrep search, ModelRetry-with-listing on misses); agents compose the subset they need. **Docstring-as-contract**: a tool docstring must state any silent filtering default of the underlying function (date windows, result caps, sort orders, index coverage) — the agent-side twin of "--help is the contract". The research agent's instructions encode a snowball workflow (seed → cites/refs → saturation); see `ko prompt research-papers` for the human-facing version. A toolset is stateless and shared by reference; each carries its own `instructions=`.
- **One file per agent** (`ai.py` = the default, `research.py`, `repo.py`, `tv.py`): ~15-50 lines — `Agent(model, instructions=..., toolsets=[...])`. Per-agent default model (research = capable, tv = cheap); `KO_AGENT_MODEL` → `[agents] model` in config.toml overrides the default at import, `-m` overrides per run (passed to the run call, not baked into the Agent).
- **`_shared.py`** — generic run/stream/repl over any Agent; streams pretty markdown to a TTY, plain text when piped. Also `preamble()`: a short shared frame (today's date in `[cal] timezone`, what a ko agent is, terminal brevity) each agent injects via an `@agent.instructions def _context` — computed per run so the date is always current (fixes agents guessing it when stamping memory).
- **Resilient tools** — each wraps its call in `_try`, returning an error note instead of raising, so one flaky source (rate limit, timeout) doesn't abort a run; the model routes to another source. Two classes of error re-raise instead: programming errors (TypeError/AttributeError/NameError/ImportError) and **`config.MissingKeyError`** — an unset key is Ko's to fix, and swallowed it makes the agent silently route around the tool for a whole run while nobody learns the key is missing. It surfaces as one clean stderr line, exit 1.
- **Search wide, read narrow** — the agent-facing `exa_search` returns *only* bounded query-biased highlights (`with_text=False`, no summary: ~6k chars for 5 hits vs ~20k with text+summary); reading in full is a deliberate second call to `exa_get`/`fetch_url`. It also exposes Exa's `category` as a `Literal` (`ko.exa.Category`, which `CATEGORIES` is derived from) so the schema hands the model an enum and the scholarly index is actually reachable.
- **Sessions** (`src/ko/sessions.py`) — every turn dumps `all_messages()` (full tool trace) to `~/.local/state/ko/sessions/<id>.json` via pydantic-ai's `ModelMessagesTypeAdapter`. Resume with `-r <id>`; list with `ko agent sessions`. Flat files in state (not config — generated, not hand-edited).
- **Memory** (`agents/_memory.py`, per docs/memory.md "v1 first") — the ai, research, repo, and tv agents each keep a writable workspace at `~/.local/state/ko/memory/<agent>/`: `memory.md` is the anchor (head-injected every run, pin marker `<!-- ko:pin-end -->` protects foundations from truncation, newest tail survives), plus any other .md notes the agent creates (listed in the injection, read on demand). Tools: `read_note`/`append_memory`/`edit_note` (uniqueness-guarded)/`write_note` (anchor protected from overwrite) — scoped to the agent's own dir, .md-only; the code `files` toolset stays read-only. Shared `~/.config/ko/memory.md` (dotfile-synced user context) injects into all memory agents; hand-edited in v1. Curation rules live in the toolset instructions (thinker's discipline).
- **Session index** (`~/.local/state/ko/ko.db`, SQLite) — `ko agent sessions summarize` writes one row per session (title ≤8 words, one-sentence takeaway, 3-5 tags) via a cheap-model structured-output call; `sessions --tag/--search` filter on it. The JSON files stay the source of truth — the DB is a rebuildable projection ("the log is the agent"). The model sees a **deterministic digest**, not the raw log: Q&A verbatim, each tool call compressed to one `[tool: name(args…) → return…]` line; trimming drops tool lines first, middle turns next, never the first prompt or final answer.
- **No YAML agent-spec**: pydantic-ai specs can't reference custom toolsets, so code factories win. Capabilities (lifecycle hooks) are deferred until we need request/tool interception.

## Adding an agent
1. Add/extend a `FunctionToolset` in `agents/_toolsets.py` if new tools are needed.
2. `agents/<name>.py` — `Agent(model, instructions=..., toolsets=[...])` + thin `run`/`repl` binding `_shared`.
3. Export in `agents/__init__.py`; add a `@agent_app.command` in `cli.py`.
4. **Close the loop — the toolset eval method** (house method for any toolset work, proven
   2026-07-10 on the files tools): after building or changing tools, (a) run the agent on 1-2
   real questions (cheap — cents), (b) have a subagent READ THE SESSION TRACES
   (`~/.local/state/ko/sessions/` keeps full tool calls/returns): flailing? repeated calls?
   params the model *invented*? (that's a tool gap — the files `grep` gained `limit` exactly
   this way), (c) a separate fresh-context adversarial review of the tool code. Each pass
   catches what the others can't: traces find ergonomics, review finds crashes, and
   prior-alignment (do names/shapes match what models are trained on — Claude Code's
   Read/Grep/Glob, rg semantics?) finds friction. The tools' heaviest user is the model —
   let it review them.

## Google auth (gsheets)
- OAuth user flow (desktop app). First command triggers browser consent, token cached at `~/.local/state/ko/google_token.json`.
- `ko gsheets auth` (or `gdocs`/`cal`/`gmail auth` — same flow) grants **one read+write token per account** covering Sheets + Docs + Calendar (write) and Gmail (read + **drafts** via `gmail.compose` — no labels/archive; sending stays config-gated). **No Drive scope** — can't browse Drive, only docs/sheets by ID. Reads use the narrower readonly scopes; the one token serves all. `--readonly` narrows; upgrade an existing token with `auth --logout` then `auth`. Adding another API later = one re-consent.
- Personal Gmail: an **External** app left in *Testing* expires the refresh token after **7 days** — set the consent screen to **Internal** (Workspace) or **Publish** the app. The token file is portable across machines (copy it, or share via `KO_STATE_DIR`).
- **Multi-account.** Active account = `-a/--account` (any `ko gsheets` cmd, sets `KO_GOOGLE_ACCOUNT`) → `[google] account` → `"default"`. Per-account token `google_token_<account>.json` (legacy `google_token.json` for `default`); per-account client `google_client_<account>.json` falls back to the shared `google_client.json` (only needed when one OAuth client can't authorize an account, e.g. a Workspace-Internal consent screen + a personal Gmail). `ko gsheets accounts` lists authed accounts. All paths via `google_auth.token_file()/client_file()/active_account()`.
- **Scope is per-API, not per-folder.** OAuth grants the tool *your* access within the scope (now Sheets only). It can't be limited to specific folders/files; true per-file scoping needs a service account (share files with its email) — a separate model not used here.
- Prereq: OAuth 2.0 Desktop client JSON at `~/.config/ko/google_client.json` (or set `KO_GOOGLE_CLIENT_FILE`). Full setup in README.

## Directories (`src/ko/dirs.py`)
- `~/.config/ko/` — user-editable config, dotfile-sync-safe (`KO_CONFIG_DIR`). `config.toml` `[keys]` table supplies API keys/tokens as a fallback to env vars (env always wins); loaded into the environment at startup so SDKs that read `os.environ` directly pick them up. A module needing a key calls **`config.require_key(name, hint)`**, which raises **`MissingKeyError(RuntimeError)`** with the how-to-get-one hint — one error type for "the human hasn't set this", distinguishable from a flaky source (see Agents) while every existing `except RuntimeError` keeps working. Non-secret settings follow the same chain via `config.setting()` (env → config.toml → baked default): `[llm] model`, `[agents] model`/`tv_tastes`, `[x] handle`, `[google] account`, `[cal] timezone`, `[publish] domain`, `[logs]`, `[telemetry]`. **Model tiers** (`llm.model_for(tier)`): `[llm] basic/medium/smart/ultra`, override per-tier in config.toml. Money-first picks (prices $/M in+out, 2026-07-31): basic = deepseek-v4-flash $0.14/$0.28 (llm default, tv, summarize, brief; v4-pro $0.43/$0.87 is the upgrade if flash quality disappoints), medium = gpt-5.6-luna $0.10/$0.60 (`ko ai`, `ko mcp overview`), smart = `~x-ai/grok-latest` $2/$6 (alias, tracks newest grok; research agent), ultra = gpt-5.6-sol $5/$30 (reserved — nothing uses it by default). luna replaced glm-5.2 ($0.97/$3.04) on 2026-07-31 — cheaper on both axes. Note medium's input is cheaper than basic's while its output is dearer (they cross at input ≈ 8× output), so basic stays the high-volume default; ultra is the only expensive tier. **Re-check these prices when you touch the tier table — the 2026-07-10 figures had drifted up to 82%.** All via OpenRouter, so `ko billing`/doctor's credits line watches the whole spend. **Per-run cost notes**: every LLM call prints `[model · in→out tok · $x]` to stderr (`llm.run_cost`/`last_cost`) — OpenRouter's actual billed cost from `provider_details['cost']` when present, else a genai-prices estimate marked `~` (which misses brand-new models → tokens only). `ko doctor` shows each key's source (env / config / missing), an effective-settings + tiers + dirs footer, warns on malformed config.toml, and live-checks the OpenRouter key via `/credits` (proves the key + shows $ left, no tokens spent).
- **`[telemetry]` — opt-in LLM telemetry** (`telemetry.py`, off by default): `enabled = true` + `POSTHOG_API_KEY` instruments all pydantic-ai agents (`Agent.instrument_all` → OTel `gen_ai.*` spans → PostHog's AI OTLP endpoint) — provider-agnostic, covers llm/agent/brief/summarize. `include_content = false` by default (metadata only — brief pipes gmail/cal through the LLM; don't mirror that to PostHog). Disabled path is one dict lookup, no OTel imports. GH issue #2.
- `~/.local/state/ko/` — tokens + id caches, never synced (`KO_STATE_DIR`); old config-dir state files auto-migrate
- `~/.cache/ko/` — disposable (`KO_CACHE_DIR`)
- `ko doctor` shows per-tool setup status (keys set, binaries found, auth done)

## Agent notes
- **`AGENTS.md`** at the repo root is the agent-facing contract (output/exit-code/`--json` conventions, bare-arg shortcuts). Keep it in sync with the bullets below.
- `ko --help` / `ko <cmd> --help` are the contract
- `ko gsheets get ... ` defaults to TSV — `cut -f N` safe
- `--json` on most read commands → a JSON array of objects (a few return a single object; `gsheets get` is a 2D array). Under `--json`: errors are `{error, code}` on stderr, empty results are `[]` on stdout. stdout = data, stderr = notes/errors.
- Exit codes: `0` success (incl. empty results), `1` runtime error, `2` usage error
- No interactive prompts inside commands (except the one-time OAuth browser popup)
